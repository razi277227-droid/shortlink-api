# shortlink-api
Сервис по сокращению ссылок на FastAPI и PostgreSQL с JWT авторизацией
## Возможности
Регистрация и вход по логину и паролю, можно отправить свою собственную ссылку,
а затем получить ее сокращенный вариант, короткая ссылка через редирект будет вести
на исходную
## Стек
Python 3.14, FastAPI, PostgreSQL 18, SQLAlchemy Core, Alembic, pytest, DockerCompose, GitHub Actions
## Быстрый старт
Нужны Docker и OpenSSL.

1. Склонировать репу:

```bash
git clone https://github.com/razi277227-droid/shortlink-api.git
cd shortlink-api
```

2. Создать `.env` из примера и поменять пароль базы:

```bash
cp .env.example .env
```

3. Сгенерировать RSA-ключи для JWT:

```bash
mkdir -p certs
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 -out certs/jwt-private.pem
openssl rsa -pubout -in certs/jwt-private.pem -out certs/jwt-public.pem
chmod 600 certs/jwt-private.pem
```

4. Запустить:

```bash
docker compose up -d --build
```
Документация API: http://127.0.0.1:8001/docs

## Локальный запуск (без докера)

Нужны Python 3.14 и локальный PostgreSQL 18, тесты подключатся через сокет без пароля

1. Окружение и зависимости (включая pytest и httpx)
```bash
python3.14 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
```

2. Две базы, для тестов и для разработки:

```bash
createdb shortlink_app_dev
createdb shortlink_app_test
```

3. Миграции в обе базы:

```bash
alembic upgrade head
DATABASE_URL=postgresql+psycopg:///shortlink_app_test alembic upgrade head
```

4. Тесты:

```bash
pytest -q
```

5. Запуск API с автоперезагрузкой (нужны ключи из быстрого старта)

```bash
uvicorn main:app --reload
```

Документация: http://127.0.0.1:8000/docs

## Эндпоинты

| Метод | Путь | Токен | Что делает |
|-------|------|-------|------------|
| POST | `/users` | нет | Регистрация, пароль хешируется Argon2 |
| POST | `/auth/token` | нет | Вход по логину и паролю (форма OAuth2), возвращает JWT |
| GET | `/users/me` | да | Текущий пользователь |
| POST | `/links` | да | Короткая ссылка со случайным кодом, можно указать `expires_at` |
| POST | `/customlinks` | да | Ссылка со своим кодом (3–20 символов), 409 если код занят |
| GET | `/r/{code}` | нет | Редирект на исходный URL, счётчик кликов +1; 404 если нет, 410 если истекла |
| GET | `/links/{code}/stats` | да | Клики и срок жизни ссылки, только для владельца |
| GET | `/links` | да | Свои ссылки с пагинацией `limit`/`offset`, сначала новые |
| DELETE | `/links/{code}` | да | Удалить свою ссылку |

## Решения и почему

- JWT подписывается по RS256: приватный ключ есть только у сервера и нужен, чтобы выдавать токены, а публичным их можно только проверять.
- Ключи не лежат в Docker-образе. Папка `certs/` добавлена в `.dockerignore`, а в контейнер ключи передаются через secrets в Docker Compose. Даже если образ утечёт, подделать токен не получится.
- На неверный логин и на неверный пароль сервер отвечает одинаково (401), чтобы нельзя было узнать, какие логины существуют. Если пользователя нет, пароль всё равно проверяется против фейкового хеша, чтобы ответ не приходил быстрее и не выдавал это по времени.
- Если запросить статистику или удалить чужую ссылку, будет 404, как будто её нет. Так нельзя узнать, что такой код уже кем-то занят.
- Удаление ссылки — один SQL-запрос с условием и на код, и на владельца. Не нужно отдельно проверять «чья ссылка», а потом удалять: всё происходит сразу.
- У ссылок есть внешний ключ на пользователя с `ON DELETE CASCADE`: если удалить пользователя, база сама удалит его ссылки.
- Для списка ссылок сделал составной индекс `(owner_id, created_at DESC, code DESC)`. Он совпадает с сортировкой в запросе, поэтому Postgres больше не сортирует строки сам. На 50 000 ссылках первая страница стала грузиться за 0.76 мс вместо 27 мс. `code` в индексе нужен, чтобы порядок был стабильным, если у ссылок одинаковое время создания.
- На далёких страницах эффект меньше (offset 40 000: было 56 мс, стало 29 мс), потому что OFFSET всё равно проходит все пропущенные строки. Это решается keyset-пагинацией.
- Тесты ходят в отдельную базу `shortlink_app_test` и перед очисткой таблиц проверяют, что подключены именно к ней.
- На каждый push GitHub Actions поднимает PostgreSQL, накатывает миграции, проверяет через `alembic check`, что модели совпадают с миграциями, и запускает тесты. Отдельно проверяется, что собирается Docker-образ.

## Ограничения и что дальше

- Пагинация через offset медленная на больших смещениях, хочу переделать на keyset.
- Нет ограничения на количество запросов, поэтому пароли на `/auth/token` можно перебирать.
- Нет refresh-токенов: токен живёт 15 минут, и раньше его никак не отозвать.
- Нельзя удалить аккаунт или отредактировать ссылку.
- В `POST /links` код сначала проверяется на занятость, а потом вставляется. Если между этими запросами кто-то успеет занять тот же код, будет ошибка 500. Шанс почти нулевой, но правильнее ловить ошибку и генерировать код заново.

## Деплой на VPS
Nginx принимает HTTP на порту 80, передает запросы на 127.0.0.1, потом возвращает обратно.
На впс config установлен в /etc/nginx/conf.d/shortlink.conf. Копия лежит в nginx/shortlink.conf

## Релиз
1. Запушить коммит и дождаться окончания тестов
2. Открыть Actions -> Deploy shortlink-api -> Run workflow, выбрать master и встаить полный SHA нужного коммита
